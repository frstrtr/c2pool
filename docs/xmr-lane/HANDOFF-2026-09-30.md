### A2: one lane position per receipt under the fee model (approved)

**Problem.** With `give_author` d > 0 (default 66), `receipt_lane_pushes` makes two pushes, so one receipt takes two window positions.

**Chosen plan: a composite lane identity.**
- New descriptor kind `XMR_LANE_GA = 0x1F` in `v37_descriptor_xmr.hpp`. Do **not** use 0x12: the P-1 fence in `v37_xmr_canon_p1_kat` forbids it.
  - Payload (132 bytes): `d u16 | payee kind+64 | donation kind+64`.
  - Codec: `make_/decode_xmr_give_author`, and `xmr_ga_split(U256 W, d)`, which gives donation = floor(W·d/65535) and payee = W − donation.
  - Validation: 1 ≤ d ≤ 65534, payee ≠ donation, never in aux or attribution. Refuse it there **before** delegating to the canon; otherwise the canon recurses.
  - `v37_descriptor.hpp` `is_xmr_dispatch_kind` gains 0x1F.
- `receipt_lane_pushes` (`xmr_fee_model.hpp`) returns exactly one push:
  - d = 0: plain `(payee, 65535)`;
  - d = 65535: `(donation, 65535)`;
  - otherwise `(composite, 65535)`.
  - Add `kFeeLanePushRule = 2`.
- `settle::project()` (`w4_settlement.hpp` ~204–224):
  - no composite seen: return exactly the old vector (fast path, byte-identical);
  - otherwise split each composite with `xmr_ga_split` into payee and donation `WeightedPayee`s, **merged by key**, dropping zero weights.
  - Every XMR consumer goes through `project()`: fold_eb, settle_block, work_price_at, credit_payees, fold_at_cut, paynow_source, share verdict.
- Relay repair shadow loader `xmr_repair_replay.hpp:242` refuses a ref longer than 64 bytes. Raise the limit to 255.
- HELLO (`xmr_relay_wire.hpp` ~999–1006): inside `if (p.fee.enabled)`, append `kFeeLanePushRule`. The gate-OFF golden `8f49947a…` does not move.
- Optional hardening in the main repair replay: `pushes.reserve(ids.size())`, and refuse when `a0 + pushes.size() != P`.

### A3 + A5: DROPS enrolment by raindrop, and DROPS paid in the block (approved)

**A5: a "DROPS due" in the ledger** (`OwedLedgerRules::drops_due`, turned on with the anchor).
- Block B's composed delta D_B is **no longer credit**. It is held in B's pending row and moves into a committed map `due` at B's FINALIZE, the moment B becomes the anchor.
- Every canonical lane block C, booked on ledger L, takes `avail = due − Σ(pending claims)`.
  - `E'_C(k) = max(0, E_C(k) + avail(k))`, applied **before** pay-now allocation and before `canon_credit_delta`.
  - Anything negative left over is written off.
  - At FINALIZE(C): `due −= claimed` (the whole snapshot), `due += D_C`.
- `due` is committed in `append_rest` as "V37U". The builder, the recompute and the share verdict all read it from the booking-point ledger inside `XmrOwedSettlementSource::build`, so it is canonical automatically.
- Arm rule: pay-now iff the view has payees OR some avail > 0. The empty-cut finder fires only when neither holds.
- A DROPS-only payee needs its ref: `ChainOrderedHarvest` keeps identity→ref, and `note_booked_refs` teaches it.

**A3.**
- The enrolment book takes the minimum of:
  1. the first lane share + 1 (as today);
  2. the ledger registry of finalized plus pending `enrol_add` records (committed as "V37G");
  3. the first raindrop bin + 1 inside the harvest range [lo, hi).
- `enrol_add` holds the new payees from (3). Everything stays ex-ante and deterministic. Gate it with `set_raindrop_enrol` (off in `make_for_test`) so the existing DROPS goldens hold.
